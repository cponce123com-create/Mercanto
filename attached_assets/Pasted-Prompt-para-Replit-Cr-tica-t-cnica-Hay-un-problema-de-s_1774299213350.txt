Prompt para Replit — Crítica técnica:
Hay un problema de seguridad importante: el token JWT se está guardando en localStorage con la clave mercanto_jwt en artifacts/mercanto/src/lib/contexts.tsx, pero en la fase anterior ya configuramos el token para que viaje únicamente en una cookie httpOnly. Tener los dos mecanismos en paralelo es inseguro porque localStorage es vulnerable a XSS.
Necesito que unifiques todo en la cookie httpOnly y elimines completamente el uso de localStorage para el token. Haz lo siguiente:
1. Eliminar el token de localStorage en el frontend
En artifacts/mercanto/src/lib/contexts.tsx:

Elimina las funciones getStoredToken, setStoredToken, clearStoredToken
Elimina la constante TOKEN_KEY = "mercanto_jwt"
Elimina la llamada setAuthTokenGetter(() => getStoredToken())
Elimina cualquier otro lugar donde se lea o escriba mercanto_jwt en localStorage

2. Asegurarse que el API client use credenciales (cookies)
En lib/api-client-react/src/custom-fetch.ts, verifica que todas las llamadas al API incluyan credentials: "include" para que el navegador envíe automáticamente la cookie httpOnly en cada request. Si no está, agrégalo como opción global en el fetch base.
3. Verificar que el backend no depende del header Authorization para nada
En artifacts/api-server/src/lib/auth.ts, la función getTokenFromRequest lee tanto el header Authorization: Bearer ... como la cookie mercanto_token. Está bien mantener el header para compatibilidad con la API directa, pero asegúrate de que el flujo principal del frontend use solo la cookie.
4. Limpiar cualquier referencia residual
Busca en todo el frontend (artifacts/mercanto/src/) cualquier uso de localStorage.getItem("mercanto_jwt") o localStorage.setItem("mercanto_jwt", ...) y elimínalos.
Después de los cambios, prueba que el login, el logout y las rutas protegidas sigan funcionando correctamente. Corre pnpm typecheck para verificar que no hay errores de TypeScript.

tsrouter.get("/stats/public", async (_req, res) => {
