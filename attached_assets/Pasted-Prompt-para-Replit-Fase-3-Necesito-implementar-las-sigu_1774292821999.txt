Genera la migración con Drizzle.
En el API server, crea un nuevo archivo artifacts/api-server/src/routes/favorites.ts con estos endpoints, todos requiriendo requireAuth:

POST /api/favorites/:storeId — agrega una tienda a favoritos. Si ya existe, devuelve 200 igualmente (idempotente).
DELETE /api/favorites/:storeId — elimina de favoritos.
GET /api/favorites — devuelve la lista de tiendas favoritas del usuario con los mismos campos que el endpoint GET /stores.


Registra las rutas en artifacts/api-server/src/routes/index.ts.
Agrega los tipos en el OpenAPI spec (lib/api-spec/openapi.yaml) y regenera el cliente con pnpm generate.
En el frontend, agrega un botón de corazón (favorito) en el componente StoreCard.tsx. El botón debe mostrar estado lleno/vacío dependiendo si la tienda es favorita. Al hacer click debe llamar al endpoint correspondiente y actualizar el estado local sin recargar.

2. Búsqueda por proximidad geográfica
El API ya tiene lat y lng en las tiendas. Necesito agregar filtrado por distancia:

En artifacts/api-server/src/routes/stores.ts, en el endpoint GET /stores, agrega parámetros opcionales de query lat, lng, y radiusKm (default 5).
Si los tres parámetros están presentes, filtra las tiendas usando la fórmula Haversine en SQL. En PostgreSQL se puede hacer así:
sql(6371 * acos(cos(radians(:lat)) * cos(radians(lat)) * cos(radians(lng) - radians(:lng)) + sin(radians(:lat)) * sin(radians(lat)))) < :radiusKm
Agrégalo como condición adicional al where usando sql template literal de Drizzle.
En el frontend, en la página de explorar tiendas, agrega un botón "Tiendas cerca de mí" que use la API del browser navigator.geolocation para obtener la posición del usuario y filtre automáticamente.
